# MeowLink-115US

MeowLink 是面向 **115US（115 版本服务端）** 的多人联机 / 组队 Mod 项目，目标是让其他服主使用自己的登录器与账号体系接入组队、同城镇可见、普通世界共享和副本共享能力。

本仓库公开 **115US 域层源码快照、部分客户端补丁源码及通用启动器 Mod 候选源码**，不包含完整服务端、游戏本体、游戏资源（PVF 等）、生产配置、客户端二进制或预编译宿主。

> **截至 2026-10-18：公开域层已完成普通组队与共享副本的离线验证；服务端 Mod 接线已在本地候选中验证，但尚未上传本仓库。原生客户端组队、进图与战斗链路尚未完成实机验收，目前没有可直接安装使用的联机发布包。**

## 接入设计

```text
服主自己的登录器
        ↓
    MeowLink 接入层
    ├─ 通用模式：目标服务器自己的账号体系
    └─ 自定义模式：自定义认证接入
        ↓
   服务端 Mod 接口
        ↓
   115US 服务端与多人域
```

两种模式共用多人域，账号与认证接入方式不同：

| 模式 | 用途 | 公开范围 |
| --- | --- | --- |
| **通用模式** | 使用目标服务器自己的用户名、密码与存档，由服主管理账号和数据库 | 本仓库公开多人域源码；完整宿主、登录器和部署配置由部署方提供 |
| **自定义模式** | 对接自定义认证与平台能力 | 自定义接入层与具体使用方式不公开 |

两种模式可面向本地或云端部署。切换模式需要清理会话并隔离存储，认证失败不得自动回退到另一种模式。

**服务端 Go Mod 接口与客户端 DLL 加载接口是两条不同的接线。** 客户端的 `ModStart` / `ModName` 用于加载客户端补丁；服务端 Mod 接口负责把经过认证的请求交给多人域。具备客户端加载器，并不表示服务端组队与原生协议已经接通。

## 当前进度

| 范围 | 已验证内容 | 当前边界 |
| --- | --- | --- |
| **本仓库公开域层** | 普通队伍容量 1–4 人；共享副本成队入口 2–4 人；多支队伍隔离；邀请代次校验；队长离队与固定槽位；Ready / Release 状态约束 | 离线领域测试，不代表 DFO 实机联机 |
| **本地服务端 Mod 候选，尚未上传** | 经真实 Mod 请求钩子调用邀请、接受、离队、队伍名单；真实 modkit 安装、自动注册、卸载与重建 | 尚未合入最新宿主基线、发布或部署 |
| **原生客户端链路** | 仓库保留部分客户端补丁与已证明逻辑体的离线解码源码 | 原生请求接入、成功响应与实机组队 / 进图 / 战斗尚未验收 |

公开域层验证为 **53 个通过的测试事件**，`go vet` 通过，记录见 [域层验证记录](docs/evidence/domain-validation.json)。

本地 Mod 候选另有 **40 个通过的定向测试事件**，宿主构建与 vet 通过；安装验证使用了 **4 个真实 TLS 认证账号和 SQLite 测试数据**，角色选择与副本内容仍为合成测试夹具。这组验证尚未随源码上传，不能视为公开仓库的测试结果，也不能视为游戏实机验证。

### 共享副本放行条件

地图实际写出后才接受对应成员的 Loaded。全员完成加载只进入 `SharedReady`；可信宿主完成资源事务并显式 Release 后，才进入 `SharedRunning`。失败、超时或成员变化不能提前放行战斗。

域层已有相关状态与守卫，但本地 Mod 候选目前只开放邀请、接受、离队、队伍名单四项操作，**尚未开放 SelectDungeon / Loaded / CommitRelease**，`NativeRequestReady=false`。详细约束见 [领域接线合同](docs/domain-contract.md)。

客户端多开相关工作保持暂停。

## 仓库内容

| 目录 | 内容 |
| --- | --- |
| `domain/` | Go 多人域：组队、普通世界共享、副本共享与协议逻辑体离线解码 |
| `client/native-party-gate/` | 原生组队门控 C++ 补丁源码，按指定客户端布局验证 |
| `client/legion-party-hud/` | 军团队员 HUD 客户端 Mod 源码，通过客户端 ModStart 宿主加载 |
| `docs/` | 架构、接入合同、来源记录与文件校验清单 |

`domain/internal/party` 提供组队、租约、招募、通知与成员投影等能力；`internal/ordinary` 提供普通共享流程；`internal/dungeon` 提供共享状态与房间事务守卫。

`internal/partywire` 只对已经单独证明的 B823 协议逻辑体进行离线解码，不推断未知字段，不生成原生成功响应，也不承担授权判定。客户端二进制更新后，需要重新验证补丁与协议布局。

## 2026-10-21 通用 Mod 候选交付

新增 `launcher/generic-host/` 与 `launcher/meowlink-mod/`，分别提供一次通用宿主扩展与可独立更新的 MeowLink 配置进程。宿主来源为 [KinkOwO/115US-launcher](https://github.com/KinkOwO/115US-launcher)，基线 `ce3dfab6533d7594ee08006899b2d57b96b1de41`，完整保留 AGPL 源码与署名；扩展及 MeowLink 维护者 zkonikishi。`launcher/` 按各目录 AGPL-3.0 许可，根 NOTICE 的非商业限制不适用于这些 AGPL 文件。

支持 Mod 栏配置页、导入摘要确认、独立更新、回滚与卸载保留配置；服务器 IP/DNS、端口与 TLS 由服主配置。自定义平台接入及真实部署配置不公开。候选未签名；摘要不代表发布者签名，原生 Mod 不等同操作系统沙箱。

本次已通过构建、宿主运行时 9 项、宿主兼容 14 项、宿主 UI 逻辑 5 项、Mod Rust 32 项和实际 Go/TLS 认证 HTTP 22 项检查；实际 Mod 进程更新/坏包拒绝/回滚已验证，宿主 EXE 无需重编。以上是不同范围的检查，不汇总成实机可用率。**原生界面视觉、实机进服、跨电脑游戏及实际 WFP 行为未验收，不是稳定可玩的联机版本。**

公开仓库只发源码与脱敏清单，不上传第三方宿主 EXE、游戏资源、配置密钥、账号数据库或原始会话日志。原生启动还需另行提供具有合法来源并符合固定摘要/严格握手协议的 ClientHost，见 Mod README；这些 Rust 源码不包含 Go 服务端接线及该宿主实现。
